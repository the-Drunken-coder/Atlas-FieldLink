# Message-centered FieldLink

1. **Time and date:** 2026-08-24, America/New_York
2. **Name:** Message modules, an explicit registry, and a retry-strategy seam
3. **Context:** FieldLink needs to carry many Atlas message kinds, preserve urgent traffic during large transfers, and avoid duplicating transport behavior already owned by MeshCore. The previous ping and benchmark wire protocol encoded test behavior directly into the runner and did not provide a durable application interface.
4. **Decision:** Each supported message owns its stable numeric ID, name, default priority, validation, binary codec, examples, hardware exercise, and optional inbound handler in one file. The exercise constructs a representative message and recognizes its end-to-end completion. A checked explicit tuple registers definitions and derives the supported TypeScript union. `FieldLinkNode` owns shared addressing, framing, scheduling, transfer bounds, hashing, reassembly, and lifecycle. Transfer repair is selected through a stable numeric and string retry-strategy seam. FieldLink registers only Test and `selective-window` strategy ID 1. FieldLink has no release numbering or wire-format field for a protocol revision. The greenfield system changes in place.
5. **Alternatives considered:** Runtime message discovery was rejected because it hides the supported protocol and complicates deterministic builds. Code generation was rejected because one handwritten message does not justify a generator. Putting fragmentation and retries in each message file was rejected because message modules would drift into separate transports. Treating every value as one MeshCore channel datagram was rejected because the 163-byte limit cannot carry the required entity and file payloads. Reimplementing MeshCore encryption, routing, duplicate suppression, or queues was rejected because the dependency and firmware already own them.
6. **Consequences:** Adding a message requires one file and one registry entry. The registry fails startup on duplicate IDs or names and invalid exercises. The CLI can list and run every registered message without message-specific transport code. The Python terminal console stays a thin CLI and evidence adapter. Application priority can preempt a transfer only between MeshCore frames. Transfers remain in memory, are limited to 1 MiB, and must restart after process failure or disconnect. MeshCore channel membership is FieldLink's only sender trust, so any channel member can spoof a FieldLink Node ID. Compression, persistent resume, replay protection, and signatures remain out of scope. Incompatible changes replace the current shape instead of adding compatibility paths or migration layers.
7. **Location:** `src/messages/`, `src/node.ts`, `src/frame.ts`, `src/retry.ts`, `src/retry-strategies/`, `README.md`, and `docs/dictionary.md`

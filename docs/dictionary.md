# FieldLink dictionary

Use these terms when discussing FieldLink, Atlas radio messages, and MeshCore. The definitions clarify names and ownership. They do not define the final Atlas wire format.

| Term                        | Meaning                                                                                                                                                                                                                                                                       |
| --------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Atlas message               | A semantic Atlas value such as a command, acknowledgement, task state, telemetry update, track report, entity snapshot, or file.                                                                                                                                              |
| Message definition          | The one-file contract for one supported message. It owns a stable `uint16` ID, name, default priority, runtime validation, binary codec, examples, hardware exercise, and optional inbound handler.                                                                           |
| Message registry            | The explicit tuple of supported message definitions. It is the source of the `SupportedMessage` type and rejects duplicate IDs or names at startup.                                                                                                                           |
| Test message                | FieldLink message ID 1. Request and response variants carry a `uint32` correlation ID and arbitrary bytes. A request is echoed exactly once; a response is never echoed.                                                                                                      |
| Resource message            | FieldLink message ID 2. A typed UTF-8 JSON envelope for Entity and Object CRUD plus Task reads. It carries no HTTP routes and does not execute operations by itself.                                                                                                          |
| Resource request ID         | The application identifier that correlates one Resource response with its request. It is distinct from the FieldLink logical ID, transfer ID, and transmission ID.                                                                                                            |
| Atlas Resource gateway      | The test-only destination adapter capability that executes a Resource request through the Atlas SDK for one preflight-approved source Node ID. It is not enabled on normal adapters.                                                                                          |
| Atlas datagram              | One complete encoded Atlas message submitted to FieldLink for delivery. FieldLink may deliver it in one MeshCore channel datagram or through a transfer.                                                                                                                      |
| MeshCore channel datagram   | The opaque application payload accepted by MeshCore `SEND_CHANNEL_DATA`. It is one MeshCore delivery unit and currently carries at most 163 bytes. Use the full name when the distinction from an Atlas datagram matters.                                                     |
| Complete frame              | A FieldLink envelope containing one numeric message type and its complete encoded body. Up to 132 message-body bytes fit in one 163-byte MeshCore channel datagram.                                                                                                           |
| Transmission ID             | A 16-bit value that changes for every intentional FieldLink frame submission. MeshCore still suppresses duplicate RF copies, while FieldLink retries remain distinct.                                                                                                         |
| Single delivery             | Delivery of an Atlas datagram in one complete FieldLink frame and one MeshCore channel datagram. Operational traffic should use this form when it fits.                                                                                                                       |
| Transfer                    | Delivery of an Atlas datagram that does not fit in one MeshCore channel datagram. A transfer divides the encoded datagram into fragments and reassembles it before Atlas decodes it. Transfer does not mean Atlas Object.                                                     |
| Fragment                    | One numbered part of a transfer. Each fragment is carried by one MeshCore channel datagram.                                                                                                                                                                                   |
| Transfer ID                 | A random 64-bit identifier shared by a transfer start, its fragments, receipts, completion, rejection, and cancellation. It lasts only for the in-memory transfer.                                                                                                            |
| Atlas Object                | The existing Atlas domain resource. Do not use `object` as the name for FieldLink transfer or fragmentation behavior.                                                                                                                                                         |
| Priority                    | The order in which FieldLink offers pending Atlas traffic to MeshCore. Priority is independent of size, so a transfer can be high priority and a small datagram can be low priority.                                                                                          |
| Retry strategy              | A registered sender and receiver state-machine pair for repairing a transfer. Framing, bounds, hashing, scheduling, and reassembly remain generic FieldLink behavior.                                                                                                         |
| Selective window            | Retry strategy ID 1. It sends windows of eight fragments and requests a bitmap receipt. A receipt timeout retries the small receipt request once after `30` seconds before any fragment repair. A received bitmap limits each of the five repair rounds to missing fragments. |
| Node ID                     | An eight-byte address derived from the SHA-256 hash of a MeshCore public key and written locally as 16 lowercase hexadecimal characters. It is not authenticated and can be spoofed by another channel member.                                                                |
| MeshCore acceptance         | MeshCore accepted a channel datagram into its outbound handling. This does not prove that another radio received it.                                                                                                                                                          |
| Delivery receipt            | FieldLink evidence that the destination received a complete Atlas datagram or specific transfer fragments. Add this only where MeshCore does not supply the required delivery evidence.                                                                                       |
| Application acknowledgement | An Atlas message reporting semantic progress such as command accepted, task started, task completed, or cancellation applied. It is distinct from MeshCore acceptance and a delivery receipt.                                                                                 |
| Mesh duplicate suppression  | MeshCore's suppression of repeated radio packets during routing. It does not replace Atlas message IDs, retry idempotency, or transfer reassembly.                                                                                                                            |
| FieldLink Adapter           | The deployed process that owns one MeshCore Companion USB radio and exposes FieldLink's single-radio interface.                                                                                                                                                               |
| Test controller             | The local process that starts two FieldLink Adapters and coordinates hardware validation. It is not part of the deployed single-radio unit.                                                                                                                                   |
| Terminal console            | The Python arrow-key interface that discovers messages and radios through the FieldLink CLI, launches the Test controller, and renders its streamed evidence. It owns no radio or delivery behavior.                                                                          |

## Ownership rule

Use MeshCore's messaging capabilities whenever they satisfy the Atlas requirement. FieldLink must inspect the exact firmware and client behavior before adding routing, encryption, packet deduplication, acknowledgements, fragmentation, retries, queues, backpressure, inboxes, or delivery metadata. FieldLink owns only the Atlas semantics and delivery behavior that MeshCore does not provide.
